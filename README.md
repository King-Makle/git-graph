# git-graph

A source control pane in the Claude desktop app's Code tab. `/git-graph` opens it; it never opens on its own. Closed by hand, it stays closed until the next `/git-graph`, and while open it comes back when you return to the session.

## Install

Paste this into Claude Code and it sets it up for you:

> Install the git-graph plugin from github.com/King-Makle/git-graph

Or run the two commands yourself:

```bash
claude plugin marketplace add King-Makle/git-graph
claude plugin install git-graph@git-graph
```

Start a new session, then type `/git-graph`. It needs `git`; the pull request features also need the GitHub CLI (`gh`) signed in. To update later: `claude plugin update git-graph@git-graph`.

## The pane

Top to bottom:

- **Header**, a card: the branch icon and the branch you are on (first letter capitalised), which opens the **Branches** card; `✿` beside it, when the repo has more than one checkout, opens the **Worktrees** card; then pills for commits ahead of and behind the upstream, `⚠ N Clashes` and `N Changed`, and a purple `⌂ Worktree` when this pane runs in a linked worktree. At the right: `↚ Undo` while one is possible, `⤓ Fetch`, `↓ Pull` (fast-forward only: when both sides moved it stops and says so), `↑ Push` (sets the upstream the first time), `≡ Draft PR` on a branch with commits its base lacks and no open PR, the `ⓘ` reference (five folding sections, one open at a time) and `↻` refresh. When the header gets tight the pills shorten first (`↑3`, `↓2`, `⚠1`, `4`), then the buttons drop to their glyphs, then `▽` stands in for a branch name that does not fit.
- **Branches**, a card opened from the branch name: every local branch, the one you are on first then the newest, with its state (`◎ Current`, `Merged`, `Not Merged`, `Remote Gone`), a cloud when origin has it, and its age. `✎ Rename` the branch you are on; `⟁ Switch` to or `✕ Delete` the rest. A delete of a branch that is not merged asks harder and is forced (`git branch -D`); `↚ Undo` brings it back. It shows 12 rows and `+ Show 12 More`.
- **Worktrees**, a card opened from `✿`: every checkout of the repo (`git worktree list`), with what it has checked out (a branch, or `Detached abc1234`) and what it is (`◎ This Pane`, `Main Checkout`, `Claude Session` for a session's `.claude/worktrees/` folder, `Worktree`, `Folder Gone`). `⎋ Open` shows the folder in Finder, `⧉ Copy Path` copies it, `✕ Remove` runs `git worktree remove` after a confirm (git refuses one with uncommitted changes; the branch stays), `⌫ Prune` clears a worktree whose folder is gone. A branch checked out in another worktree is purple everywhere: a `⌂ Session` or `⌂ Worktree` pill on the Branches card with `⎋ Open` and `⧉ Copy Path` in place of Switch and Delete (git refuses both), a house on its History chip, and its folder named on an open commit. A detached worktree's commit gets a chip with its folder.
- **Changes**, always, as a card: `Changes` and the file count with `☑ All`, `＋ Stage` and `❏ Stash` at the right; the message box with `✎ Write` and `Commit` inside it; then the files in two groups: **Staged Changes** (what is in the index, with `Unstage All` and a `−` on each row) and **Changes** (what differs from the index, a `✕` discards after a confirm). Each row has a checkbox, its status letter and its name; a file edited after it was staged is in both groups. A checkbox only *selects*: nothing runs when you tick it. `Commit` is dim until there is a message and a tick; it adds the ticked files as they are on disk now and commits exactly those (files staged another way and not ticked stay staged). `＋ Stage` stages the ticked files; `❏ Stash` shelves them (everything when none or all are ticked). `☑ All` ticks everything (`□ None` clears). Click a file name for its diff under the row.
- **Stashes**, while any exist: a dashed teal marker, the ref, the message, the file count, and `Apply` / `Pop` / `Drop` (Drop confirms).
- **History**, a card: the last commits across all refs, SVG lanes, a hollow dot at HEAD; each row an author-initials avatar, the subject, pill chips for branches, remotes and tags, then `author · age` at the right edge (a narrow pane drops the author so the ages stay in one column).

Click a commit to open its card: the avatar, subject, author and date, `⧉` to copy the hash and `↗ GitHub`; the message (a long one clipped, `▸ More`); `▸ N Files` with a diffstat per file and a diff under each; the other local branches on it, each with `✕ Delete` (or `⎋ Open` when another worktree holds it); and the actions in groups, offering only what changes something for where the commit sits relative to HEAD: **Go To It** (`↪ Check Out` as a detached HEAD, `＋ Branch`, `# Tag`), **Undo On Main** (`↺ Revert`), **Bring Into Main** (`↓ Cherry-Pick`, `⤵ Merge`, `↑ Rebase Onto`) and **Rewrites Main** (`⇤ Reset Here`, soft). Each asks first in a confirm line; a cherry-pick, revert, merge or rebase that stops on a conflict is aborted and reported, so the pane never leaves the repo mid-operation.

**Keeping up with a collaborator.** The History card shows who did what and what has not been pulled yet:

- **Author colours.** Each person has a colour on their avatar, their commit's dot and the stems of their branch lane: you are blue, everyone else one of six colours chosen from their name (never orange or red). The trunk (your branch and the upstream's first-parent line) keeps neutral grey stems. Names come through the repo's `.mailmap`, so a person who commits under two names becomes one colour once you add a `.mailmap` line; the pane never edits it.
- **Incoming band.** After a fetch, commits on the upstream that you have not pulled are drawn with a dashed hollow dot on a blue tint, under a band `↓ N incoming from origin` with a `↓ Pull` button.
- **Clash ring.** An incoming commit that changes a file you have also changed gets an orange ring and `⚠ touches your <file>`; the header shows `⚠ N Clashes` (the number of your changed files affected).
- **Main Line.** The `Main Line` button in the History header swaps the lane graph for `git log --first-parent`: each merged pull request is one row (`▸ #34 title`, `+A −D`, `N commits`, its authors' avatars). Click a merge row to list the commits it brought in; click a plain commit as usual. `Full Graph` swaps back. The choice is remembered across sessions.
- **Teammates.** With the gh CLI signed in, a card above History lists other people's open pull requests and recent branches on origin, newest first: avatar in their colour, the branch, how many commits it is ahead of main, its PR (`#12 open`, `#13 draft`) and checks, its age. Click a row to see the PR title, its commits and files; **Check Out** switches to the branch, **Open On GitHub** goes to the PR or the branch. It refreshes every minute and after a fetch or pull. An open PR also shows as a pill on its branch's tip in the graph.
- **Show More.** History draws the newest 25 commits (or Main Line rows) and ends with `+ Show 25 More` and `N Older`; each press adds 25, up to the 150 the pane loads, then a note says so. Switching branch or view starts over at 25. The incoming band stays on top.
- **Auto-fetch.** Off until you turn it on with the switch in the Settings section of the ⓘ panel (the choice is remembered). While it is on and the pane is open, a quiet `git fetch --prune` runs every 5 minutes, so incoming commits, clashes and teammates appear on their own. It toasts only when new commits arrive and says so once if origin cannot be reached.
- **A closed pane does nothing in the background.** The 15-second refresh, the GitHub lookups and auto-fetch all pause while you have the pane closed; `/git-graph` (or returning to the session) reads everything fresh.

**Undo** puts the last pane action back (a commit becomes staged changes again, a reset or merge returns to where HEAD was, a stash is popped, a tag is deleted). It goes away after a push, or once anything else moves HEAD.

The drawing stays at or under 222 buttons, the most the live desktop draws: file rows with buttons cap at 30, stash rows at 8, the Branches and Worktrees cards take theirs while open, and the commit list shrinks from 150 toward 40 as they grow. The pane refreshes every 15 seconds, after any git command Claude runs, and at the end of each turn. A `reload` tool lets Claude drive the pane without clicking (select a commit, start and confirm an action, stage, commit, sync, stash, undo, open the Branches or Worktrees card and act on a row) and bisect a drawing the desktop refuses (`probe`, `show`, `cut`, `level`, `dump`); it is a dev aid and can go.

Files: `hooks/register.tsx` wires events, state and git; `hooks/git.ts` parses git's output (status, log, stashes, branches, worktrees); `hooks/actions.ts` is the command table (argv, confirm text, abort, inverse); `hooks/pane.tsx` composes the header, the reference and the History rows from `hooks/changes.tsx`, `hooks/stashes.tsx`, `hooks/detail.tsx` (the commit card), `hooks/branches.tsx` (the Branches card) and `hooks/worktrees.tsx` (the Worktrees card); `hooks/fit.ts` estimates widths so labels shorten only when they must; `hooks/editor.tsx` is the multi-line message box (a Client surface); `hooks/section.tsx` draws a section card, `hooks/chips.tsx` the ref chips, glyphs and colours and shortens dates and names, `hooks/diff.ts` the diff helpers, `hooks/svg.ts` the lanes, pills, count pills, avatars, icons and spacers, `hooks/graph.ts` the lane layout, `hooks/people.ts` author colours and lane tints, `hooks/selection.ts` the ticked files, `hooks/incoming.ts` the not-pulled and clash parsers, `hooks/band.tsx` the incoming band, `hooks/mainline.ts` and `hooks/mainview.tsx` the Main Line view, `hooks/teammates.ts` the teammate parsers, join, commands and PR badges, `hooks/teammatesview.tsx` the Teammates card, `hooks/draft.ts` the Write and Draft PR prompts, `hooks/pr.ts`, `hooks/prcard.tsx` and `hooks/summary.tsx` the pull request flow, `hooks/autofetch.ts` the quiet-fetch rule, `hooks/budget.ts` the button budget.
